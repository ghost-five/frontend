# Золотые тесты движка

Набор снимков: позиция, ходы обоих игроков и состояние, которое должно получиться.
Это **исполняемое описание правил** — главный артефакт для переписывания движка
на другом языке. Пройденный набор значит, что новая реализация считает партию так
же, как нынешняя.

## Формат

Один файл — один случай, `fixtures/cases/NNN-имя.json`:

```jsonc
{
  "name": "магниты сцепились",
  "why":  "оба якоря тянут одну фишку: не едет никто, обоим кулдаун",
  "cfg":  { "size": 9, "win": 4, "secret": true, ... },  // правила партии
  "before": { ... },   // полное состояние ДО хода
  "play": {            // что сыграли
    "mode": "round",   // round — тайный ход обоих, seq — ход одного, resign — сдача
    "moves": { "1": { "i": 40, "kind": "magnet" }, "2": { "i": 40, "kind": "magnet" } }
  },
  "after": { ... }     // полное состояние ПОСЛЕ
}
```

Поля `play` по режимам:

| mode | поля | что делает |
|---|---|---|
| `round` | `moves: {1, 2}` | тайный ход: оба хода применяются одновременно |
| `seq` | `seat`, `move` | обычный ход одного игрока |
| `resign` | `seat` | игрок сдаётся |

Состояние (`before`/`after`) — то же дерево, что лежит в `games.state`; его поля
описаны в [DEV.md](../DEV.md). Поля хода — там же, в разделе «Ход».

Поля намеренно маленькие (7×7 и 9×9): фикстуру должно быть видно глазами, а
правила от размера поля не зависят.

## Как прогнать

```
node tools/fixtures-check.mjs     # проверить текущий движок
node tools/fixtures.mjs           # пересобрать набор после правки правил
```

Проверка печатает первое расхождение с путём до поля, например
`after.cells.40: 1 ≠ 0` — по нему сразу видно, что разъехалось.

## Для реализации на другом языке

1. Прочитать `cfg` и `before`, применить `play` своим движком, сравнить с `after`.
2. Сравнивать **по значению, а не по тексту**: порядок ключей в объектах не важен,
   порядок элементов в массивах важен (очередь памяти `q`, журнал `log`, снимки
   `frames` — упорядоченные).
3. Журнал (`log`) сравнивать тоже: события — это часть правил, а не оформление.
   Человеческий текст из них собирает клиент, в движке лежат только ключи и поля.
4. Числа целые, дробных в состоянии нет.

## Чего набор не покрывает

- **бота** — он играет со случайностью, его поведение не фиксируется;
- **сеть, рейтинг, историю** — это задачи сервера, у них свои тесты;
- **оформление** — цвета, анимации и тексты журнала живут в клиенте.

## Правило работы

Правила меняются — набор пересобирается тем же коммитом, и разница в `after`
просматривается глазами в код-ревью. Если diff в фикстурах вас удивил, значит
правка задела больше, чем вы думали.
