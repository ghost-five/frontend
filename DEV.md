# Карта проекта

Записка для того, кто продолжит работу над Ghost Five. Про саму игру и настройку Supabase — в [README.md](README.md); здесь то, что нужно знать перед правкой кода.

## Из чего всё состоит

| Файл | Что внутри |
|---|---|
| `engine.js` | Правила игры и бот. Чистые функции над обычным JSON-состоянием, никакого DOM. Одинаково работает в браузере и в Node (`require('./engine.js')`) |
| `app.js` | Всё остальное: экраны, рендер, звук, часы, работа с Supabase. Один IIFE, внутри разбит комментариями-секциями |
| `index.html` | Разметка всех экранов сразу; лишние скрыты атрибутом `hidden` |
| `styles.css` | Переменные тем и палитр, затем блоки по экранам |
| `supabase.sql` | Таблицы, функции, триггеры и правила доступа. Повторный запуск безопасен |
| `vendor/` | Библиотека Supabase локально, чтобы не зависеть от чужих CDN |
| `tools/` | Тестовый стенд: на сайт не попадает, игре не нужен |

Сборки нет: файлы подключаются как есть, порядок в `index.html` — `config.js`, `vendor/supabase.js`, `engine.js`, `app.js`.

## Состояние партии

Весь ход партии лежит в одном объекте `st`, который целиком пишется в `games.state`. Поля:

```
n, cells[]        поле: 0 пусто, 1 и 2 — игроки, 3 стена
q{1,2}            очередь фишек для короткой памяти (порядок = возраст)
anchors[]         клетки якорей; anchorSet{клетка: ход} — когда поставлен
anchorLeft{}      якорей в запасе (всего ANCHORS = 2)
shots{}, caps{}   выстрелы и захваченные пары
walls[[i, ttl]]   стены; ttl = 0 значит «стоит вечно»
scar[[i, чей]]    след от сбитой фишки, живёт один ход
bank{}, clean{}   запас времени и серия ходов без его траты
magnetCd{}        магнит остывает, если два якоря схватились за одну фишку
misses{}          пропуски подряд (MISS_LIMIT = 3 — поражение)
frames[]          снимки поля для перемотки: {t: тег, c: строка клеток, l: последние, s: следы}
round, moves, turn, starter, gameNo, over, winner, winLine, winReason, last[], log[], fx{}
```

`fx` живёт один рендер: `fresh` — поставленные, `gone` — исчезнувшие, `slide` — пары «откуда-куда» для анимации магнита, `burn` — сгоревшая клетка.

## Ход

Ход — это объект `{ i, kind, take, spent }`:

- `kind`: `place`, `anchor`, `shot`, `moveAnchor`, `magnet`, `pass` (и старый `unanchor` — он остался ради партий, начатых прежней версией);
- `take` — клетка якоря, который заодно возвращается в запас, или `false`. Возврат **не считается ходом**;
- `spent` — сколько секунд взято из запаса времени;
- `from` — якорь, которым тянет магнит, если игрок выбрал его правой кнопкой.

**Тайный ход** в сети идёт через хеш. Порядок полей в строке хеша менять нельзя, не сломав партии, которые уже идут:

```
gameNo | round | i | kind | anchor(0/1) | take(-1 или клетка) | spent | [a<from>] | salt
```

Предпоследний кусок появляется, только когда игрок назвал якорь (`a40`). Без него строка ровно та же, что была до выбора якоря, поэтому прежние ходы считаются по-старому. Так же дописывается и любое будущее необязательное поле: вставлять его в середину нельзя.

Тот же набор уходит в `moves.reveal`, и при раскрытии каждый игрок пересчитывает хеш сам. Если не сошлось — ход считается пропуском.

## События журнала

`st.log` — массив записей `{tag, ev[], kind}`. Каждое событие — `{k, p, i, ...}`. Текст из них собирает `evParts()` в `app.js`: возвращает массив кусочков, где `{nm: игрок}` — ник в его цвете, `{pos: клетка}` — адрес вроде `D7`. Новые события добавляются в оба места: движок кладёт ключ, `evParts` его расшифровывает. Старые ключи лучше оставлять понятными — в идущих партиях они уже записаны (так живёт `cool` рядом с нынешним `wallGone`).

## Экраны

`R.route` — один из `auth, play, online, game, top, look, profile, rules, archive`. `go(route)` меняет маршрут, `routeGuard()` не пускает дальше входа без аккаунта и дальше профиля без ника. Важные тонкости:

- `online()` — это `route === 'game'`, то есть «мы на экране сетевой партии». Для вопроса «я в сетевой партии вообще» есть `inOnlineGame()`;
- открытая сетевая партия не закрывается при уходе в другой раздел: вкладка «По сети» возвращает в неё, а выход — кнопкой «Все партии»;
- карточки «Правила партии» и «Интерфейс» существуют в одном экземпляре и переезжают между экранами (`placeRules`).

## База

- Состояние партии пишут сами игроки; доверие между ними держится на правилах доступа, а не на сервере.
- Рейтинг считает база: `report_result` читает сохранённое состояние, применяет Эло и ставит партии отметку «учтена». Триггер `profiles_guard` не даёт игроку править себе рейтинг мимо этой функции.
- История партий лежит в таблице `history`: один доигранный раунд — одна строка, владелец видит только свои (RLS по `owner`). Сетевой раунд кладут себе оба игрока, по записи каждому; от повторов спасает частичный уникальный индекс по `(owner, code, game_no)`. Хранятся последние 50 раундов по 50 ходов, лишнее подчищает сам клиент. Игрок без аккаунта обходится `localStorage`.
- `supabase.sql` нужно выполнять заново после правок схемы. Так было при появлении рейтинга, при расширении правила удаления партий, при переводе Эло на счёт партии и при появлении таблицы `history`.

## Тестовый стенд

Боевой Supabase требует подтверждённых почтой аккаунтов, поэтому сетевая часть проверяется на подмене: `tools/mock-supabase.js` выдаёт клиент, который хранит всё в `localStorage`, а две вкладки одного браузера играют друг с другом.

Стенд поднимается один раз в своём окне терминала, сценарии ходят на тот же адрес:

```
node tools/stand.mjs                  # http://localhost:8778/?as=1 и ?as=2
node tools/scenarios/play.mjs         # партия с другом по сети
node tools/scenarios/cancel.mjs       # отмена отправленного хода
node tools/scenarios/rewind.mjs       # перемотка ходов
node tools/scenarios/archive.mjs      # архив и просмотр партии
node tools/scenarios/medal.mjs        # рейтинг и медали
node tools/scenarios/match.mjs        # партия до двух побед, счёт кружками
node tools/scenarios/anchors2.mjs     # два якоря, меню магнита, памятка по наведению
node tools/scenarios/hold.mjs         # пауза перед ходом
```

Сценарии водят настоящий Chrome через `tools/cdp.mjs` (запуск, клики, измерения, скриншоты). Почти все начинают с `localStorage.clear()` и выключают паузу перед ходом (`{hold:0}`) — иначе каждый ход ждёт отсчёта.

Мок — не Postgres: он не проверяет правила доступа и события приходят через `storage`, поэтому обновления в нём доходят медленнее. Из-за этого в сценариях щедрые паузы. Подробнее — в [tools/README.md](tools/README.md).

## Что осталось непроверенным

Живая партия двух аккаунтов на боевом Supabase: нужны два подтверждённых почтой логина. Всё остальное — схема, функции, правила доступа — проверялось запросами к проекту напрямую.
